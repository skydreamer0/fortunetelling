# CI reliability and bounded work (#96)

## Observed baseline

CI [#131](https://github.com/skydreamer0/fortunetelling/actions/runs/38028009130/job/114142881831)
used Bun 1.4.3 and completed 1619 pass / 2 existing live-Claude skips / 0 fail,
118 files in 451.99 seconds. The subsequent master
[#132](https://github.com/skydreamer0/fortunetelling/actions/runs/38028638631/job/114144730961)
was cancelled near the 10-minute job budget. Several earlier files were about
1.4–1.5 times slower; reportGolden had only just started. Timeout pressure is an
inference, not proof of a hung golden or concurrency cancellation.

## Conservative classification

Only pull requests modifying exclusively the audited root README.md/ROADMAPS.md,
or exclusively the five existing favicon/icon files, use the scoped lane.
These must be modifications, not additions, deletions or renames. The exact
allowlist is in scripts/ci/pipeline.ts. All source, tests, fixtures, dependencies,
lockfiles, workflows, other documents, manifest/service-worker files, mixed or
unknown changes use full regression. Unreadable diffs default to full.

In particular docs/MCP-SETUP.md is read by docsSync and docs/validation may be
browser acceptance input; there is no blanket docs/** exclusion. Extending the
allowlist requires reviewing source/test/build consumers and adding cases.
Master pushes and manual CI always use full regression. No premerge result,
cross-run artifact or exact-tree success is reused to skip master tests.

Scoped checks retain all CI-policy tests, docsSync, PWA unit tests, all four
package typechecks, CI-control typecheck, MCP doctor and production build.
The built-asset check verifies copied public bytes, PNG headers/dimensions,
manifest icon references, app-shell/precache membership and compiled PWA version.
It is structural evidence, not visual, real-browser or mobile acceptance.
Existing browser and Windows workflows retain their specific acceptance scope.

## Complete isolated partitions

scripts/ci/test-durations.json records the observed #131 file durations. Four
longest-first balanced partitions cover the current tracked Bun test inventory
exactly once, using all Bun default suffixes and excluding hidden/dependency
directories. New tests are discovered automatically with a conservative default
weight. Missing, duplicated, empty or incompatible discovery configuration fails.
The original golden, fixture bytes, export inventory, replay, TZ subprocess
controls and test assertions are unchanged.

Each job starts an isolated Bun process and passes explicit ./file paths rather
than substring filters. It requires normal completion, zero failures and the
exact expected file count. Tests remain sequential within a process; no global
concurrent mocks, fake clocks or TZ mutation were introduced. Matrix fail-fast
is disabled so other partitions produce diagnostics after one fails. Ten minutes
remain available per shard; splitting improves wall-clock time, not total CPU.
Runtime is pinned to the observed baseline Bun 1.4.3 for generic CI and deployment;
the existing browser/Windows acceptance workflows remain pinned to their own
previously reviewed Bun 1.4.2 contracts.

The existing Test & Build check name remains the aggregate. It always runs and
accepts only successful classification/build checks plus either every full
partition or the explicitly selected scoped lane. Missing, cancelled, failed or
unexpectedly skipped jobs cannot pass. The aggregate exports the verified exact
checkout SHA only after acceptance.

## Deployment and validation

Pages is a reusable workflow called only after successful full master-push CI.
The existing Pages scopes are relocated to the trusted publication job and
narrowed within the reusable workflow. There is no independent deployment push
or manual trigger. Exact accepted/event/checkout SHA, repository, event, branch,
current master and same-run artifact identity are checked. A fresh master read
is repeated immediately before publication; it is not an atomic lock with future
pushes. No PR artifact is promoted and no new token scope is introduced.

Local commands (run from repository root):

- bun test ./scripts/ci/pipeline.test.ts ./scripts/ci/assets.test.ts ./scripts/ci/pages-gate.test.ts
- bun scripts/ci/pipeline.ts plan
- bun scripts/ci/pipeline.ts run 0 (repeat for 1, 2, 3)
- bun scripts/ci/pipeline.ts run lightweight
- bun run --cwd apps/web --bun tsc -p ../../scripts/ci/tsconfig.json
- bun run --filter @fortune/core typecheck (also web, ai, mcp)
- bun run packages/mcp/src/cli/doctor.ts --ci
- bun run build && bun scripts/ci/assets.ts

Actual final results, independent review and any unrun acceptance are recorded
in the PR/Issue receipt. Do not infer production/browser acceptance from these
commands being documented or from a build succeeding.
